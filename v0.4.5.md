# v0.4.5

<!-- shuku:locale=zh-CN:start -->
## 简体中文

本版本建立了移动应用基础，加入服务器连接、健康检查与本地配置持久化，并实现受容量约束的阅读进度文档与可靠快照存储。移动端现已具备独立的类型检查、测试与 CI 验证链路，为后续原生阅读体验奠定了可持续演进的基础。

导入能力升级为持久化、有界的工作队列与流式目录扫描。监控目录、批量扫描、上传和有声书轨道发现现在拥有更明确的背压、幂等、恢复与安全边界，减少大型书库扫描时的内存压力、重复入队和异常中断风险；相关数据库迁移、ADR 与回归覆盖已同步补齐。

Web 应用升级到 Next.js 16，并通过统一 HTTP 网关协调 Web 与 Python API 流量。书库访问、导入上传授权、PDF 与 EPUB 阅读器兼容性、响应式 PWA 外壳以及系统事件展示均得到修正，同时保留中英文界面的一致性。

后台任务现在会一致地识别 SQLite 锁竞争，回滚并释放失败事务后使用新会话进行可中断的有界重试，避免元数据查询与整理调度因瞬时写竞争反复报错。发布和开发镜像工作流、双语问题反馈模板及版本一致性校验也已完善。

## English

This release establishes the mobile application foundation with server connection, health checks, persisted local profiles, capacity-bounded reader progress documents, and reliable snapshot storage. The mobile workspace now has dedicated type checking, tests, and CI validation so native reading capabilities can evolve on a stable base.

Imports now use a persistent bounded work queue and streaming directory scans. Monitored folders, batch scans, uploads, and audiobook track discovery have clearer backpressure, idempotency, recovery, and security boundaries, reducing memory pressure, duplicate queue entries, and interruption risk for large libraries. The corresponding database migration, ADRs, and regression coverage are included.

The Web application has moved to Next.js 16 and now coordinates Web and Python API traffic through a unified HTTP gateway. Library access, import upload authorization, PDF and EPUB reader compatibility, the responsive PWA shell, and system event presentation have been corrected while preserving complete Chinese and English interfaces.

Background tasks now classify SQLite lock contention consistently, roll back and release failed transactions, and retry with fresh sessions using an interruptible bounded policy. Release and development image workflows, bilingual issue forms, and application-wide version consistency checks have also been strengthened.
