# 测试执行分层

本项目按风险和反馈速度选择测试，而不是让每次改动都执行全量回归。这里的分层只控制**何时执行**测试；它不降低代码质量门槛，也不允许删除仍保护公开契约、授权、迁移、恢复或数据安全的测试。

## 日常开发与 PR

先执行改动能力对应的测试文件，再执行所在应用的静态检查。不要以全量回归替代有针对性的测试选择。

移动端工作流在受影响路径上执行：

- 后端的移动兼容和认证契约测试；
- 共享/Android 单元测试、lint 和 debug 构建；
- `AndroidShellSmokeTest`，覆盖应用启动、登录入口、根导航和中英文资源。

这套默认集不再重复执行完整 Python 套件，也不把所有 Android 仪器测试当作“冒烟”运行。

## 完整回归

在发布候选、跨能力重构、数据库迁移、鉴权边界调整或问题影响面不明确时，执行完整回归：

- 后端：`cd apps/api-python && uv run --extra dev --locked pytest -q`；
- Web：`cd apps/web && pnpm lint && pnpm typecheck && pnpm test && pnpm test:e2e`；
- Android：从 Mobile 工作流手动触发，并启用 `run_full_android_regression`；
- iOS：只在已连接、配对且可用的物理设备上执行构建、测试和运行时验收。禁止用 Simulator 作为替代证据。

## 维护规则

新测试应只在它保护一个明确的缺陷、契约、不变量或恢复路径时加入。若两个测试覆盖同一用户结果，保留更接近公开边界、失败信息更清晰且执行成本更低的那个；删除另一个前，必须确认它不覆盖不同角色、失败路径、格式、设备或恢复状态。

每次测试规模异常增长时，审查测试属于日常、能力集成、发布回归还是物理设备验收，并把执行入口放到相应层级。
