## API 及手机消费者

这些改动保持协议 3，未删除既有默认响应字段。

| 接口变化 | 行为 | 手机处理 |
| --- | --- | --- |
| 新增 `GET /api/library/navigation-sources` | 只返回 `data.sources` 的 `id,name` | KMP `KtorContentRepository.loadLibraryOptions` 已切换，避免仅为名称读取筛选统计 |
| 新增 `GET /api/shelves/navigation` | 返回自有书架 `id,name,kind,collectionIds` | KMP `KtorShelfRepository.loadShelves` 首次目录请求已切换 |
| `GET /api/books?view=import-status` | 显式选择时只取 `id,libraryId,metadataState,resourceImportSummary` | 压测验收用途；手机正常图书页保留原视图 |
| 书架 `includeBookIds` | GET 保持原行为；POST/PATCH 新增可选参数，缺省仍为 true；false 不返回完整成员 ID | 手机分页已有 false；本轮创建请求补为 false；普通列表仍因展示计数/预览使用汇总接口 |

新手机访问旧协议 3 服务器时，两个新导航接口仅在 HTTP 404 时回到旧接口。认证、网络及服务器错误原样传播；测试覆盖 401/403/500 不触发兼容请求。适配器归属上述 KMP 仓储，停止支持导航接口之前的协议 3 服务器时移除。旧手机访问新服务器仍使用原默认契约。

尚未解决：单本图书的书架归属选择需要 `containsBook`，现有手机仍逐个请求书架成员 ID。导航适配没有消除这部分 N+1；需要后续增加按单本图书返回归属的最小接口，并同步 Web/手机相关消费者，不能直接省略 ID 后误报未加入。

## 数据库兼容与迁移

新增 14 个正式线性迁移，最新为 `0058_search_candidate_covers`，没有改写已发布迁移。

| 迁移 | 内容 |
| --- | --- |
| 0045–0048 | 来源子节点、导入任务页、来源清理页和任务状态统计索引 |
| 0049–0053 | 图书身份列表、导入状态页、搜索覆盖、目录成员覆盖索引替换、最近导入分页索引 |
| 0054–0056 | 资源筛选、按书汇总、资源身份覆盖索引 |
| 0057 | 派生 FTS5 搜索表、存量填充及增删改触发器；中断后通过正式迁移重建派生数据 |
| 0058 | 搜索候选授权范围和标题覆盖索引 |

这 14 项不删除或重定义原业务列；0052 替换旧索引。正式迁移运行器的离线豁免通过 finally 清除，不带入在线连接。已有历史迁移可能包含当时明确的退休数据处理，本结论不能推广为所有历史迁移从不删数据。

使用 NAS 同一镜像、Python 3.11 / SQLite 3.40.1、真实后端 `15499bde`，通过 SQLite backup 获取只读一致性副本；升级走正式 `apply_schema`。比较升级前后每张原业务表的行数及全部字段 SHA-256：小库按主键排序；大库顺序读取并将 rowid 纳入哈希，WITHOUT ROWID 表按主键排序。运行 integrity_check、foreign_key_check、搜索与元数据数量比较及第二次启动。没有通过手工改库填补数据。校验会预热页缓存，实测不是清空系统缓存后的冷启动保证；升级计时期间业务容器继续运行。

| 样本 | 初始版本与规模 | 快照耗时 | 正式升级耗时 | 再次启动 | 结果 |
| --- | --- | --- | --- | --- | --- |
| 正式库只读副本 | 0044；66,306,048 B；92 条元数据 | 52.359 s | 0.389 s | 0.045 s | 业务表哈希不变、完整性通过、无外键错误、FTS 92 条 |

大库 14 个升级步骤分别耗时：0045 3.864 s、0046 2.936 s、0047 1.890 s、0048 0.907 s、0049 3.698 s、0050 1.651 s、0051 1.651 s、0052 10.528 s、0053 2.559 s、0054 4.559 s、0055 1.768 s、0056 1.794 s、0057 6.273 s、0058 3.091 s。最慢的是 0052，包含约 7.775 秒的旧索引删除；0057 中存量搜索数据填充 SQL 约 4.035 秒。用于构造旧结构的正式降级另耗时 66.553 秒，不属于正常升级路径。辅助容器最终退出码 0，完整逐步耗时、SQL 和业务表哈希见 `results-sequential.json`。

正式库样本是真实旧版库，大库样本是旧结构兼容与规模压力验证，不能冒充历史原始大库。第一次大库在线 backup 未固定读快照，被持续写入反复重启；已停止该辅助容器，保留证据。第二次在只读事务中固定 WAL 快照再 backup，567.423 秒完成。最初按主键随机读取的全表哈希开销较大，停止该校验辅助进程后复用完整快照，以顺序读取加 rowid 哈希继续验证；原脚本、未完成记录及新 `results-sequential.json` 均保留。这些准备/校验时间不计为迁移耗时，也未停止业务容器。

上述 SQLite backup 仅用于创建隔离验证副本，不是迁移或镜像更新自动触发的步骤，也不是更新前置要求。实际更新遵循当前 ADR：停止旧服务、替换程序和依赖、启动，由应用负责初始化、校验与正式迁移；不新增数据库备份或预检步骤，不自动回滚。升级失败保留完整日志及失败状态。迁移耗时不等于包含程序同步和服务启动的总耗时。此阶段未执行正式发布。
