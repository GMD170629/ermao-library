# ADR 0021: 书库扫描触发与冲突协调

- 状态：已接受
- 日期：2026-08-24

## 背景

书库导入此前只在上传、启用或手动操作时创建扫描任务。worker 只消费任务，不观察文件系统，也没有周期对账，因此进程运行期间直接放入书库的新文件可能永远不会入库。若各入口直接执行扫描，又会产生并行扫描、重复导入和 SQLite 写冲突。

## 决策

实时事件只负责触发，周期扫描负责对账，单消费者队列负责冲突控制。

- `RequestLibraryScan` 是所有书库扫描触发源的唯一应用入口。
- 文件监听回调只写入内存缓冲；数据库入队由 import worker 主循环执行。
- 新建和移入事件经过 5 秒静默窗口合并。静默窗口内的修改事件只延后已经待处理的新建事件，既有文件的独立修改不触发扫描。
- 所有启用书库共用持久化的周期设置。周期扫描用于补偿停机、监听不可用和事件丢失，不替代实时监听。
- 每个书库数据库级最多保留一个 `QUEUED` 和一个 `RUNNING` 的 `SCAN_LIBRARY`。运行期间允许一个后续任务，后续事件继续合并到该任务。
- 只有显式手动“继续导入”会重试失败资源。启动、监听、周期、上传和启用触发不会重试历史失败任务。
- worker 启动、书库集合变化或监听重建时请求一次启动对账扫描。

## 后果

新增内容能低延迟入库，同时所有扫描仍串行执行。监听失败不会阻断 worker，最迟由周期扫描补回。既有文件修改、移出和删除仍不在本阶段同步范围内，后续完整生命周期能力需要另立 ADR。
