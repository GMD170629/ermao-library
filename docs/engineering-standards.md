# 工程实现规范

全仓执行原则见 [AGENTS.md](../AGENTS.md)，实际能力入口见 [当前代码结构](business-code-layering-and-refactoring.md)。本文规定实现边界，不要求每次补丁执行架构迁移。原因、预期与影响范围明确时，优先在现有职责位置修正直接错误。

按本次任务读取适用章节。测试应保护下述契约与不变量；何时执行、选择多大范围、何时停止，统一按 [测试执行策略](testing/test-execution-policy.md)。

## 目录与职责

按业务能力组织，内部按需要分层。以下是目标布局示例，不是每个能力必须创建的文件清单；不建空层级、转发文件或无实际用途的端口、DTO、状态机。

| 范围 | 目标归属 |
| --- | --- |
| Python | `app/modules/<capability>/{domain,application,infrastructure,presentation}`，`public.py` 暴露公开入口；`bootstrap` 装配依赖；`db` 管理模型与迁移 |
| Web | `features/<capability>/{api,model,application,ui}`，`public.ts` 暴露公开入口；`app` 保持薄路由与装配 |
| 共享代码 | 稳定且业务中立的基础设施放在共享层，须已有至少两个真实消费者；能力特有逻辑留在其所属能力 |
| 测试 | 按能力组织领域、应用、仓储、API、迁移和关键交互测试；复用已有入口，不为局部补丁搬迁测试目录 |

不增加万能 `utils`、`helpers`、`managers` 或通用 `services` 收容目录。既有目录和旧模式不构成新增同义实现的理由；也不因目录不符合示例就自动迁移可用代码。

## Python 实现

### 领域与应用

- 目标 Python 3.11，公共函数、方法和属性有明确类型。领域包含实体、值对象、不变量与纯规则，可脱离框架、ORM、文件系统和网络测试。
- 应用用例表达用户意图，负责授权决策调用、编排、事务边界与副作用顺序；不依赖 FastAPI Request/Response 或具体 SQLAlchemy 实现。
- 领域输入和结果优先不可变 dataclass 或校验后的值对象，外部边界使用 Pydantic；不向领域传 Request、Response、ORM 实体、数据库行或任意字典。
- 稳定边界不用 `Any`。动态外部输入先接收为 `object`，校验后映射为明确类型。
- 纯行为优先纯函数；类用于注入依赖、生命周期或有意义的状态。避免用布尔模式将无关流程塞入一个函数。
- 不使用可变模块级业务状态、可变默认参数、通配符导入、隐藏猴子补丁或导入时 I/O。进程协调归属显式运行对象或持久存储。
- 名称表达业务含义，避免缺少上下文的缩写与泛称。提取函数应改善职责或测试边界，不为缩短行数创建转发层。

### 数据库与受控遗留 SQL

新增数据库能力使用 SQLAlchemy 2.x ORM 或类型化表达式；禁止新增手写 SQL、`sqlalchemy.text()`、文本 `execute()`、`exec_driver_sql()`、直接 `sqlite3`、裸游标或字符串查询片段作为新能力实现。

已定位的遗留 SQL 缺陷允许在原有查询与职责位置做必要局部修正，无须先迁移 ORM。此例外只适用于原失败及同一根因的直接消费者，不允许复制 SQL 管线、新增通用原始 SQL 工具、绕过参数绑定、引入不可信输入拼接或放宽授权。验证查询结果、必要反例与受影响契约；ORM 迁移作为独立任务，不阻塞已充分验证的小修复。

- 表与关系使用 `Mapped[...]`、`mapped_column()`；读使用 `select()`、关系、加载策略、`Session.scalars()` 和类型化投影；写使用映射实体或确需集合操作时的 `insert()`、`update()`、`delete()` 表达式。
- 持久化归属能力仓储或查询对象，按聚合/用例命名。返回领域对象或显式 DTO，ORM 实体不泄漏到 HTTP、React 或无关能力。
- 明确加载策略避免 N+1，不返回无界对象图；分页有确定顺序与文档化最大页大小。
- 应用用例通过现有工作单元/端口决定事务边界，适配器用 `session.begin()` 或等价机制实现；仓储可 `flush()`，不隐藏 `commit()`/`rollback()`。不为简单修复新增事务框架。
- 完整性异常只有在可转为明确领域/应用冲突时才捕获，并保留原因；不吞错或把失败当成功。

### 数据库迁移

- 新迁移使用 SQLAlchemy schema 对象及迁移框架操作，显式定义表、列、索引、外键、唯一约束和默认值；SQLite 重建使用 batch/table-copy 或 schema API，不手写 DDL、PRAGMA 或 `INSERT ... SELECT`。
- 迁移有序、确定、可识别重入与部分完成，发布后不可改写。已发布迁移的缺陷通过后续修复迁移处理，不能套用遗留 SQL 例外修改历史版本。
- 昂贵回填与结构变更分离，使用 ORM/类型化表达式、有界批次和恢复位置；迁移不导入运行期应用服务。
- 迁移变化验证空库、受影响的支持升级路径、重复执行、部分完成与失败恢复；这不自动触发无关应用回归。

### HTTP、Worker 与集成

- FastAPI 路由负责解析校验、取得 actor/依赖、调用一个应用命令或查询、映射结果与命名错误；不承载 ORM 查询、业务决策、文件操作、媒体解析或跨服务编排。
- JSON 端点使用显式 Pydantic 请求/响应契约（无请求体不需虚构模型），稳定端点不返回任意字典。除明确变更外保持路径、方法、状态、错误码、信封及授权兼容。
- 资源授权在用例内验证，不能仅依赖路由前缀保护。分支使用错误类型/代码，不依赖本地化消息。
- API、Worker、调度器和 CLI 复用应用用例，互不调用对方展示层。Worker 边界负责轮询、租约、重试退避、关闭、确认和最终失败处理。
- 广泛 `except Exception` 仅用于进程/任务隔离边界，记录上下文并明确重试、隔离或终止，不静默吞错。
- 外部系统、文件系统、转换器、时钟、随机 ID 和 SDK 在适配边界后；优先复用现有接口，不为小修复建立通用集成框架。
- 文件发布采用临时写、校验、原子替换；实际跨数据库/文件系统流程明确幂等键、可恢复中间态与失败恢复。

## TypeScript 与 React 实现

### 类型与契约

- 保持 strict，业务代码禁止 `any`、宽泛断言、非空断言、`@ts-ignore` 和未校验 JSON 强转。
- 网络、存储、URL、postMessage 和浏览器持久化输入作为 `unknown`，边界校验后进入领域。
- 有 OpenAPI 等权威 schema 时生成稳定 wire 类型；生成文件不手改。
- DTO、领域、视图与表单的语义、校验责任或生命周期不同时分离；相同稳定契约可复用，不为每一层复制等价类型。ORM、框架对象不能因此跨越领域边界。
- 多阶段工作流优先判别联合、reducer 或现有状态机表达有效状态；不为已隔离的条件错误新建状态机。

### API 与状态归属

- `fetch()` 只在共享 API transport 或能力 API client 适配层；组件、页面、provider、reducer 和 model 不直接请求。
- 共享 transport 统一 base path、凭据、取消、content type、信封解码、会话过期信号和传输错误；能力 API 校验端点响应并映射为模型。
- UI 处理命名应用结果，不按原始状态码或后端本地化文案分支。视图变化或卸载时，异步操作支持取消或拒绝过期结果。
- model 保持框架无关；application 协调查询、修改、服务端状态和乐观更新；UI 渲染模型并发出用户意图，不解析信封或实现持久化规则。
- 外部经 `public.ts` 使用能力，共享 UI 不导入业务能力；Next.js 路由仅作装配，不充当跨能力业务目录。
- 可分享导航归 URL，服务端事实归应用层/cache，瞬时视觉状态归组件，跨页会话归显式 store/runtime；不维护等价状态副本。
- `useEffect` 用于外部同步，不用于计算派生状态或串联内部业务转换；没有外部同步契约时不镜像 props/服务端状态。保持完整依赖，不关闭 `react-hooks/exhaustive-deps` 强行控制时机。

### UI 与资源生命周期

- 能力公开模块用命名导出，框架要求除外。组件保持内聚，不为减少行数添加纯转发包装。
- 可独立表达的纯业务规则优先命名纯函数；含 I/O 的业务流程归应用用例，简单展示表达式不必机械提取。
- 避免布尔属性堆积，按实际需要选择组合、变体或明确状态；不因偏好“更优雅”重写可用实现。
- 纯 model 不访问 `window`、`document`、storage；定时器、订阅、observer、object URL 和监听器有明确清理与所有者。
- memoization 依实测需要使用，不替代正确状态归属。
- 保持适用的键盘、指针、触摸、焦点、减少动态效果与屏幕阅读器行为。

## 跨语言工程要求

### 事务与副作用

对实际存在的写流程说明并验证授权/校验、当前状态与决策、临时写入、提交/发布顺序及失败恢复。只覆盖适用步骤，不为了凑齐流程引入队列、事件、补偿或报告系统。简单补丁可以复用现有用例与测试说明。

禁止隐藏提交、fire-and-forget 和无主后台任务；新增或改变的副作用须有明确所有者和失败结果。

### 错误、安全与授权

- 保持小而明确的能力错误分类；翻译基础设施失败保留 cause。仅在能补充上下文、映射、补偿、重试或隔离失败时捕获异常，禁止空 catch 和回退为成功。
- 不在用户错误中暴露秘密、内部路径、SQL 或堆栈；秘密不进入源代码、日志、样例、快照和生成物。
- 校验并规范化外部输入，数据库查询按 actor/资源范围约束，不能全量加载再内存过滤；保持 not-found/forbidden 的反枚举行为。
- 不信任客户端声明的归属、角色、路径、MIME、文件名或长度。文件路径相对配置根解析并检查穿越与符号链接逃逸。
- Reader 安全语义与验证义务遵循根规则引用的唯一机器契约，不为局部问题新增平台私有策略。

### 可观测性

复用现有日志设施，在有诊断价值的外部入口、重要写操作、后台任务和失败恢复边界记录稳定事件、相关标识、阶段与结果；安全时包含 actor/目标范围。区分校验、授权、冲突、基础设施失败、重试与终止。不要记录整份请求、书籍正文、token、cookie、密码或提供方凭据，也不为每个小用例新建日志/指标框架。

### 国际化

目标是本次用户可见变化完整支持 `zh-CN`/`en-US`，不将此要求写成全项目已验证的现状结论。

- 检查本次影响的标题、按钮、输入提示、错误、空态、toast、对话框、无障碍、metadata、PWA、邮件、生成文件及后端状态等实际输出，不重审无关功能。
- Web 复用 `apps/web/i18n`，新增应用文案提供中文与有意编写的英文；原生与非 DOM 输出使用对应既有本地化边界。
- 插值参数保持一致；书名、作者、标签、系列、书架、路径、文件名等用户内容不翻译。
- 日期、时间、数字、百分比和相对时间使用当前 locale，不硬编码 `zh-CN`；错误码与事件类型保持语言中立。
- 复用对应双语验证；新增输出或行为缺少覆盖时补定向检查。Web 文案、翻译目录或本地化行为变化按测试策略运行 `pnpm i18n:check`，不提交缺键、残留未译应用文案、陈旧键或插值不匹配。

## 测试设计与质量底线

测试对应真实契约和故障层级，选择和停止条件见测试策略。以下按适用风险选择，不要求每次全部执行：

| 层级 | 保护内容 |
| --- | --- |
| 领域 | 不变量、边界和状态转换，脱离框架与数据库 |
| 应用 | 使用自有端口 fake 验证编排、授权、事务结果与实际副作用顺序 |
| 仓储 | 真 SQLite/ORM 的约束、关系、分页、加载与回滚；遗留 SQL 修复测实际查询契约 |
| API | 方法、路径、状态、信封、字段、错误码与角色/资源授权 |
| 迁移/Worker | 受影响升级路径；幂等、重试、租约、关闭、中断与恢复 |
| Web/原生界面 | 纯规则、交互、无障碍与原失败界面；底层通过不等于界面通过，E2E 只覆盖必要关键链路 |

断言可观察行为，不绑定私有实现细节；优先 mock 自有端口，不逐个 mock 内部函数。测试中的时间、随机性、文件根和外部系统可控制。已有测试足够则复用，不为每个补丁新建入口。

不得删除有效断言、跳过失败、放宽阈值、缩减功能或反复重跑取一次成功。保持严格度和覆盖率门槛，禁止全局忽略或宽泛 suppression；工具确实无法表达已证明安全的代码时，局部说明原因。新警告处理；触及代码的既有警告按本次关联与风险处理，超出范围的明确记录，不顺手全仓清理。覆盖率是风险信号，不能替代失败边界证据。

## 有界重构

本节只用于用户明确要求的重构或解决直接原因所必需的结构调整，普通补丁不自动进入此流程。

确认影响范围与现有归属 → 保持公开契约和不变量 → 在需要的位置提取规则/类型或调整端口/职责 → 切换范围内调用方 → 删除被替换的重复实现、状态和回退 → 按测试策略验证。阶段按实际需要选择，不强制每次拆层或创建类。

跨能力的持久决策需要 ADR；局部条件修复不需新建 ADR。遗留 SQL 按受控例外局部修复，ORM 迁移另行安排。临时兼容只能委托唯一实现，有明确归属和退出条件；不以“以后优化”豁免重复实现。

## 缺陷排查示例

页码显示错误先定位该页码的转换、映射或展示位置，定向检查同一根因的直接消费者。复测原界面页码和实际受影响的首末页等反例；没有证据涉及下载、同步或导航状态时，不重演导入、断网、跨端和进程强杀。具体新反例或失败才触发继续调查。
